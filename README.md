# Cartridge Tracker 🖨️

Полноценная система учета и контроля оборота картриджей в организации с веб-интерфейсом, развертыванием в Docker, интеграцией с Active Directory (LDAP), отправкой уведомлений в WhatsApp через шлюз Evolution API и формированием готовых к печати актов А4.

---

## 🌟 Ключевые возможности

1. **Без аппаратных сканеров штрихкодов**:
   - Быстрый «живой» поиск картриджей по надписи маркером (например, `«Каб. 204 #1»`, `«Бухгалтерия-2»`).
   - Поддержка считывания QR-кодов через камеру устройства (ноутбука, смартфона или планшета) прямо в браузере.
2. **Динамические настройки из интерфейса**:
   - Все параметры (LDAP/Active Directory, Evolution API, шаблоны сообщений, наименование организации для актов) сохраняются в базе данных SQLite и применяются «на лету» без перезапуска контейнера.
3. **Полный 4-этапный жизненный цикл картриджа**:
   - **Приемка**: поиск или заведение картриджа, выбор сотрудника из базы Active Directory (автокомплит) -> статус `pending_vendor` (*Ожидает заправщика*).
   - **Передача поставщику (Акт)**: выбор позиций, указание сервисного центра -> перевод в статус `at_vendor` (*На заправке*) + формирование печатного акта А4 (`window.print`).
   - **Возврат и оповещение WhatsApp**: отметка приехавших позиций -> перевод в статус `ready_for_pickup` (*Готов к выдаче*) + рассылка персональных сообщений через локальный шлюз Evolution API.
   - **Выдача**: ввод номера маркера -> проверка кабинета и владельца -> перевод в статус `in_use` (*В работе*).
4. **Аудит и история**:
   - Логирование каждого перемещения и действия с фиксацией времени, инициатора и примечаний.

## 🚀 Быстрый запуск

### 1. Предварительные требования
- Установленный **Docker** и **Docker Compose**.

### 2. Запуск контейнеров
В корневой папке проекта выполните команду:

```bash
docker compose up -d --build
```

После завершения сборки и старта будут доступны сервисы:
- **Веб-интерфейс Cartridge Tracker**: [http://localhost:8080](http://localhost:8080)
- **WhatsApp Gateway (Evolution API)**: [http://localhost:8081](http://localhost:8081)
- **База данных SQLite**: автоматически сохраняется в папке `./data/cartridges.db` на хосте.

## ⚙️ Первый вход и настройка (UI)

Откройте в браузере [http://localhost:8080](http://localhost:8080) и перейдите во вкладку **«Настройки»**:

### 1. Вкладка «Active Directory / LDAP»
1. Укажите параметры подключения к вашему доменному контроллеру:
   - **LDAP Сервер**: например, `ldap://192.168.1.10:389` или `ldaps://dc.company.local:636`
   - **Base DN**: например, `DC=company,DC=local`
   - **Учетная запись (Bind DN)**: например, `CN=svc_ldap,OU=Service,DC=company,DC=local` или `svc_ldap@company.local`
   - **Пароль учетной записи**: введите пароль
   - **Атрибуты**: настройте имена атрибутов (по умолчанию `displayName`, `physicalDeliveryOfficeName`, `department`, `mobile,telephoneNumber`).
2. Нажмите кнопку **«Проверить подключение»** — система выполнит тестовый bind.
3. Нажмите кнопку **«Синхронизировать пользователей сейчас»** — система выгрузит актуальный список сотрудников с кабинетами и телефонами в локальную базу.

### 2. Вкладка «WhatsApp (Evolution API)»
1. Параметры по умолчанию уже настроены на совместную работу контейнеров в docker-compose:
   - **URL шлюза**: `http://whatsapp-gateway:8080` (внутри сети docker)
   - **API Key**: `cartridge_secret_key_2026`
   - **Имя инстанса**: `cartridge_bot`
2. Нажмите кнопку **«Получить QR-код»** прямо в интерфейсе:
   - Откроется модальное окно с QR-кодом.
   - Откройте WhatsApp на корпоративном смартфоне -> **Связанные устройства** -> **Привязка устройства** и отсканируйте QR-код.
3. Нажмите **«Проверить статус»** — индикатор загорится зеленым (*«Подключен»*).
4. Проверьте отправку тестового сообщения в блоке **«Тестовая отправка сообщения»**.
5. При необходимости скорректируйте **Шаблон сообщения**:
   > Переменные шаблона: `{name}` (ФИО), `{marker}` (надпись маркером), `{model}` (модель картриджа), `{cabinet}` (кабинет), `{it_office}` (куда подойти).

### 3. Вкладка «Общие настройки и реквизиты»
1. Заполните:
   - **Наименование организации** (подставляется в шапку акта передачи А4)
   - **Местоположение IT-отдела** (подставляется в сообщения сотрудникам)
   - **Поставщик по умолчанию** (название сервисного центра по заправке)
   - **Префикс номеров актов** (по умолчанию `АКТ-`)
2. Нажмите синюю кнопку **«Сохранить настройки»**. Настройки сразу применятся без перезапуска!

## 📋 Рабочий процесс оператора

### Этап 1: Приемка
- Пришел сотрудник с картриджем.
- Введите надпись с корпуса маркером (например, `Каб. 204 #1`) или нажмите иконку **Камера (QR)**.
- Если картридж уже был в системе — данные подтянутся автоматически. Если новый — укажите модель и кабинет.
- В поле **Сотрудник** начните вводить фамилию — отобразится список из Active Directory с телефонами и отделами.
- Нажмите **«Принять на заправку»** -> статус меняется на `pending_vendor`.

### Этап 2: Передача поставщику (Формирование акта)
- Приехал курьер сервисного центра.
- Перейдите во вкладку **«2. Акт передачи»**.
- Отметьте картриджи для передачи (или оставьте «Выбрать все»).
- Нажмите **«Сформировать акт передачи и распечатать»**.
- Картриджи перейдут в статус `at_vendor` (*На заправке*), и автоматически откроется готовая печатная страница А4 с реквизитами, таблицей и местами для подписей заказчика и исполнителя (`window.print`).

### Этап 3: Возврат и оповещение WhatsApp
- Курьер привез заправленные картриджи.
- Перейдите во вкладку **«3. Возврат и WhatsApp»**.
- Отметьте галочками позиции, которые приехали, и нажмите **«Принять с заправки (Готов к выдаче)»**.
- Позиции перейдут в статус `ready_for_pickup`.
- Нажмите кнопку **«Оповестить готовые в WhatsApp»** — система отправит персональные сообщения каждому сотруднику/кабинету через шлюз Evolution API и выведет отчет об отправке.

### Этап 4: Выдача
- Сотрудник пришел забрать картридж в IT-отдел.
- Перейдите во вкладку **«4. Выдача»** и введите надпись маркером (или считайте QR).
- Проверьте соответствие целевого кабинета и сотрудника.
- Нажмите **«Выдан (перевести в работу)»** -> статус картриджа переходит в `in_use` (*В работе*).

## 🛠️ Локальный запуск для разработки (без Docker)

Если вы хотите запустить проект локально в среде Python:

```bash
# 1. Создание виртуального окружения
python -m venv venv
venv\Scripts\activate   # для Windows
source venv/bin/activate # для Linux/macOS

# 2. Установка зависимостей
pip install -r requirements.txt

# 3. Запуск сервера FastAPI
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Приложение будет доступно по адресу [http://127.0.0.1:8000](http://127.0.0.1:8000).
